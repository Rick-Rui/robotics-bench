# Tasks whose [agent].timeout_sec has already been lifted past the 5h authoring
# cap, one slug per line. check-task-timeout.sh exempts these from the authoring
# cap; the hard 8h cap still applies to them.
#
# Why this file exists: a task is AUTHORED at 5h so its /run trials fit inside the
# GitHub runner's 6h job limit (run-trials.yml pins timeout-minutes: 360, and no
# setting raises that), leaving ~1h for build and verifier. Before a release the
# whole suite is lifted to the 8h published budget, because benchmark runs happen
# on Modal via Harbor Hub where the runner limit does not apply. This file records
# which tasks have been through that lift, so raising the suite does not have to
# mean weakening the rule for the next contributor.
#
# At the next release lift, regenerate it after editing the task.tomls:
#
#   python3 - <<'EOF' > ci_checks/timeout-lifted-tasks.txt
#   ... (keep this header, then append the slugs over 18000) ...
#   EOF
#
# Note check-instruction-suffix.sh requires instruction.md's "You have N seconds"
# to equal [agent].timeout_sec, so a lift edits both files in every task.
